# 앱 스토어용 페이지 - 작업 문서

조요피(JOYOPI)가 만드는 모바일 앱의 **스토어 제출에 필요한 공개 페이지**를 joyopi.com에 만든다(2026-11-12 결정). 지금 작업 중인 앱은 두 개다.

| 앱 | 코드 저장소 | 사업 문서(스토어 이름·번들 ID·수익 모델) |
| --- | --- | --- |
| **돌보기** | `apps/dolbogi` | [dolbogi.md](../../business/dolbogi.md) |
| **아기록** | `apps/agirok` | [agirok.md](../../business/agirok.md) |

돌보기는 계정·서버·광고가 없고(기기 안에만 저장), 아기록은 계정(Google·Apple 로그인, Firebase)과 AdMob 광고가 있다. 이 차이로 필요한 페이지가 갈린다.
사업 정보의 정본은 저장소 밖 `apps/business` 폴더다. 이 문서에는 다시 적지 않고 링크한다.

앱 쪽 기준 문서
- 돌보기: `apps/dolbogi/docs/developer-tasks.md`(결정 목록), `docs/ios-release.md`, `docs/android-release.md`
- 아기록: `apps/agirok/docs/decisions.md`(결정), **`docs/privacy-policy.md`(개인정보처리방침 원고 — 내용은 이 파일이 기준)**

## 1. 왜 필요한가

페이지마다 왜 필요한지(스토어 요건·근거)는 [사업 문서: joyopi.com](../../business/joyopi.md) 1장이 기준이다.

## 2. 만들 것

아래 경로는 스토어에 등록한 **언어 없는 주소**다. 실제 페이지는 `/ko/…`, `/ja/…`, `/en/…`에 있고, 언어 없는 주소로 들어오면 브라우저 언어의 페이지로 보낸다(10장).

| 경로 | 내용 |
| --- | --- |
| `/` (홈) | 회사 한 줄 소개, 두 앱 카드, 최근 소식, 문의 안내. 사업자 정보는 모든 페이지의 공통 푸터에 있다 |
| `/apps`, `/apps/rockgazing`, `/apps/agirok` | 앱 목록과 앱별 소개(특징·기기·언어·가격·스토어 링크). 스크린샷은 출시 때 더한다 |
| `/apps/rockgazing/privacy` | 돌보기 개인정보 처리방침(ko/ja/en) |
| `/apps/rockgazing/support` | 돌보기 지원(ko/ja/en) |
| `/apps/agirok/privacy` | 아기록 개인정보처리방침(ko. ja·en 주소는 번역 준비 중 안내 + 한국어 본문, 7장) |
| `/apps/agirok/support` | 아기록 지원(ko/ja/en) |
| `/apps/agirok/delete-account` | 아기록 계정·데이터 삭제 안내와 요청 방법(ko/ja/en) |
| `/app-ads.txt` | AdMob 판매자 선언 한 줄(아기록). 언어와 무관하게 이 주소 그대로 |

각 경로를 스토어의 어느 입력란에 넣는지는 [사업 문서: joyopi.com](../../business/joyopi.md) 2장이 기준이다.

공통 조건
- **로그인 없이** 누구나 열린다(스토어 심사자가 연다). 사이트에 로그인이 없다(2026-11-12 제거). 프록시(`proxy.ts`)는 언어 없는 9개 주소의 언어 리다이렉트만 한다(10장). 쿠키 동의 팝업 등으로 본문을 가리지 않는다.
- 정적 페이지(서버 액션·DB 없음). 바뀔 때마다 맨 아래 **시행일/최종 수정일**을 바꾼다.
- 모바일 폭(390px)에서 가로 스크롤 없이 읽힌다. 사이트 공통 헤더는 있어도 되지만 본문이 첫 화면에 보여야 한다.
- 언어: 두 앱 모두 **ko/ja/en**(2026-11-13 결정, [사업 문서: joyopi.com](../../business/joyopi.md) 2장 「언어」). 언어마다 따로 된 페이지에 그 언어 하나만 보여 준다(10장). 예전에 한 페이지에 세 언어를 둘 때 쓰던 앵커(`#ja`, `#en-collect` 등)는 도착한 페이지가 그 언어 주소로 넘긴다.
- 앱마다 같은 틀(제목·시행일·목차·문의)을 쓰는 공통 컴포넌트 하나에 내용만 바꿔 넣는다. 사업자 정보는 한 곳(상수)에 두고 모든 페이지가 가져다 쓴다.
- 페이지 `<title>`: 「Rockgazing 개인정보 처리방침」, 「아기록 개인정보처리방침」처럼 앱 이름 + 페이지 이름.
- `app-ads.txt`는 `public/app-ads.txt` 정적 파일로 두고 `text/plain`으로 나가는지 확인한다.
- 사이트 전체 구성(대표 메뉴·푸터·에코)은 [프로젝트 정의서](./00_조요피연구소.md) 4장이 기준이다. 사업자 정보는 모든 페이지의 공통 푸터에 그 페이지의 언어로 나온다(영어·일본어 페이지는 영문 주소·대표자 표기).

코드 위치
- 사업자 정보 상수: `app/apps/_lib/business-info.ts`(값이 `null`인 항목은 화면에 줄이 나오지 않는다), 앱 목록: `app/apps/_lib/apps.ts`(언어별 이름·소개·특징, 스토어 주소가 `null`이면 「출시 준비 중」)
- 공통 틀: `app/apps/_components/doc-page.tsx`, 사업자 정보 표: `app/apps/_components/business-info.tsx`, 공통 문구 사전: `app/_i18n/dictionary.ts`
- 페이지: `app/[lang]/page.tsx`(홈), `app/[lang]/apps/{rockgazing,agirok}/…/page.tsx` — 언어별 본문(`ko`·`ja`·`en`)과 시행일·최종 수정일이 각 파일에 있다

## 5. 아기록 페이지 내용

### 5-1. 개인정보처리방침
- **원고는 `apps/agirok/docs/privacy-policy.md`가 기준이다.** 이 문서에 내용을 다시 적지 않는다. 페이지는 그 원고를 옮기고, 원고가 바뀌면 페이지도 고친다.
- 옮길 때 원고의 빈칸(보호책임자·연락처·시행일)을 3장 값으로 채운다.
- 아기록은 서버(Firebase)에 개인정보를 저장하므로 한국 개인정보보호법의 처리방침 필수 항목이 원고에 모두 있는지 확인하고, 빠진 것은 **원고(agirok 저장소)에 먼저 더한 뒤** 페이지에 옮긴다. 확인할 항목: 처리 목적·항목, 보유·이용 기간, 파기 절차·방법, 제3자 제공, 처리 위탁(Google·Apple), **국외 이전**(Firebase Analytics·Crashlytics·AdMob 등 미국 Google LLC로 가는 정보: 이전 국가·항목·시기·방법·보유기간), 정보주체 권리와 행사 방법, 안전성 확보 조치, 자동 수집 장치(광고 식별자)와 거부 방법, 보호책임자, 변경 고지.
- 아기(아동) 건강 관련 정보를 다룬다는 점, 육아 기록을 광고에 쓰지 않는다는 점을 눈에 띄게 둔다.

### 5-2. 지원
1. 앱 소개 한두 줄(한 손·한 번 탭으로 끝나는 육아 기록).
2. 문의 `hello@joyopi.com`.
3. 자주 묻는 질문: 기기를 바꾸면(같은 계정으로 로그인하면 이어 씀) / 공동양육자 초대(6자리 코드, 24시간) / 광고 제거 결제(가족 계정 전체 적용, 다른 기기에서 복원) / 환불(스토어로) / 탈퇴·데이터 삭제(`/apps/agirok/delete-account` 링크).
4. 사업자 정보(3장).

### 5-3. 계정·데이터 삭제 안내 (Google Play 계정 삭제 URL)
- 앱 이름과 개발자(JOYOPI)를 맨 위에 적는다(Google이 확인하는 항목).
- **앱에서 지우는 법**: 설정 › 「탈퇴하고 데이터 지우기」 단계별 안내(iOS에서 Apple 로그인이면 Apple 로그인을 한 번 더 받아 Apple 토큰도 취소된다).
- **앱 없이 요청하는 법**: 로그인에 쓴 계정 이메일로 `hello@joyopi.com`에 「아기록 계정 삭제 요청」을 보내면 지운다. 처리 기간([사업 문서: joyopi.com](../../business/joyopi.md) 4장)을 적는다.
- **지워지는 것 / 남는 것**: 계정과 내 기록은 지체 없이 지움. 다른 공동양육자와 함께 쓰던 아기의 기록은 그 사람들이 계속 볼 수 있음(원고 2장). 법령상 보관할 것(결제 기록은 스토어가 보관)이 있으면 적는다.

### 5-4. `app-ads.txt`
- 내용: `google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0` (AdMob 게시자 ID는 AdMob 계정을 만든 뒤 사용자에게 받음 — agirok 「사람이 해야 하는 출시 절차」의 AdMob 항목).
- 스토어(App Store 「마케팅 URL」 또는 「지원 URL」의 도메인, Google Play 「개발자 웹사이트」)에 적은 도메인이 `joyopi.com`이어야 AdMob이 찾는다.
- 돌보기에 광고를 붙이게 되면 같은 파일에 줄을 더한다(지금은 없음).

## 10. 다국어 구조 (2026-11-13)

결정은 [사업 문서: joyopi.com](../../business/joyopi.md) 2장 「언어」가 기준이다.

**주소 규칙**
- 앱 관련 페이지(홈, `/apps`, 앱 소개, 처리방침, 지원, 계정 삭제)는 `/{lang}/…`(`ko`·`ja`·`en`). `app/[lang]/` 아래에 있고, 이 폴더의 `layout.tsx`가 루트 레이아웃이라 `<html lang>`이 주소의 언어를 따른다.
- 소개(`/about`)·소식(`/news`)·회사 지원(`/support`)·약관·정책(`/policies`)·메아리(`/echo/**`)는 한국어만, 주소에 언어가 없다. `app/(korean)/` 아래, 루트 레이아웃은 `lang="ko"`. 공통 메뉴는 일본어·영어 화면에서도 이 페이지로 링크한다(`hreflang="ko"`).
- `/app-ads.txt` 등 `public/` 정적 파일과 API 경로는 언어와 무관하다.
- 각 언어 페이지에 `canonical`(지금 언어)과 `hreflang` 대체 주소(ko·ja·en, `x-default`는 언어 없는 주소)를 둔다(`app/_i18n/page.ts`의 `localizedMetadata`). 헤더에 언어 전환 링크가 있다(같은 페이지의 다른 언어, 한국어 전용 페이지에서는 각 언어의 홈).
- 어느 경로에도 맞지 않는 주소는 `app/global-not-found.tsx`(세 언어 404, `next.config.ts`의 `experimental.globalNotFound`).

**리다이렉트**(`proxy.ts`, 규칙은 `app/_i18n/config.ts`)

| 들어온 주소 | `Accept-Language` | 가는 곳 |
| --- | --- | --- |
| 언어 없는 9개 주소(2장 표의 `/`·`/apps…`) | 선호도가 가장 높은 ko·ja·en 중 첫 번째 | `/{그 언어}{같은 경로}`, **307**(임시), `Vary: Accept-Language`, 쿼리 문자열 유지 |
| 〃 | ko·ja·en이 없음(예: `fr`), 헤더 없음 | `/en{같은 경로}` |
| 〃 + 예전 앵커 `#ja`·`#en-collect` 등 | — | 위 리다이렉트 뒤, 도착 페이지가 앵커의 언어 주소로 넘김(`legacy-hash-redirect.tsx`) |
| `/echo/**`, `/news`, `/about`, `/policies`, `/support`, `/app-ads.txt`, 정적 파일 | — | 리다이렉트 없음(matcher 밖) |

**새 페이지 추가 방법**
1. 언어별 페이지면 `app/[lang]/…/page.tsx`를 만들고 `resolveLang(params)`로 언어를 받는다. 본문은 `const DOCS: Record<Lang, DocLocale> = { ko, ja, en }`처럼 세 언어를 한 파일에 둔다. `generateMetadata`에서 `localizedMetadata(lang, '/언어 없는 경로', …)`를 돌려준다.
2. 메뉴·홈 같은 공통 문구는 `app/_i18n/dictionary.ts`에 ko 기준으로 세 언어를 함께 더한다(타입이 빠진 언어를 잡는다). 앱 이름·소개는 `app/apps/_lib/apps.ts`의 언어별 `text`.
3. 링크는 `localePath(lang, '/apps/…')`로 만든다. 언어 없는 주소로 걸면 리다이렉트를 한 번 더 거친다.
4. 한국어만 둘 페이지는 `app/(korean)/` 아래에 둔다.
5. 그 페이지의 언어 없는 주소가 이미 밖(스토어 등)에 등록돼 있으면 `LEGACY_PATHS`(`app/_i18n/config.ts`)와 `proxy.ts`의 `matcher`에 같이 더한다(matcher는 빌드 때 정적으로 읽혀 상수로 다시 적는다). `proxy.test.ts`가 둘이 맞는지 본다.
