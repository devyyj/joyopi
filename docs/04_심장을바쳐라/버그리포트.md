# [버그 리포트] 신게키 테스트 공유 URL 결과 미표시 오류

본 문서는 '심장을 바쳐라!' 서비스 운영 중 발생한 기술적 결함과 그 해결 과정을 기록한 이력 관리 문서입니다.

---

## 1. 이슈 개요 (Issue Overview)

*   **발생 일자**: 2026년 6월 2일
*   **이슈 제목**: 공유 URL로 진입 시 테스트 완료 후 결과 미표시 및 화면 튕김 현상
*   **영향 범위**: 신게키 테스트 페이지 (`/shingeki`)
*   **심각도**: 높음 (사용자의 최종 경험인 결과 확인이 불가능함)

---

## 2. 현상 상세 (Symptoms)

1.  사용자가 특정 캐릭터의 결과가 포함된 공유 URL(예: `?c=에렌%20예거`)로 접속함.
2.  공유된 결과를 확인한 후 '다시 하기' 버튼을 클릭하여 테스트를 시작함.
3.  12문항의 답변을 모두 마친 후 '분석 중' 화면에서 결과 화면으로 넘어가지 않고 멈춰있거나, 초기 홈 화면으로 튕기는 현상 발생.
4.  간헐적으로 다시 하기 직후 이전 공유 결과 화면으로 강제 이동되는 레이스 컨디션 발생.

---

## 3. 원인 분석 (Root Cause Analysis)

### 3.1. 공유 파라미터 처리 로직의 결함
*   `useEffect` 내에서 `hasProcessedShareLink` 플래그를 `setTimeout`으로 관리하고 있었으나, URL의 쿼리 스트링이 완전히 제거되기 전에 플래그가 초기화되면서 `useEffect`가 재실행되어 이전 결과를 다시 띄우는 레이스 컨디션이 발생함.

### 3.2. Next.js Suspense 경계 누락
*   `useSearchParams` 훅을 사용하는 컴포넌트가 `Suspense` 경계로 감싸져 있지 않아, 클라이언트 사이드 하이드레이션 과정에서 파라미터 읽기 시점이 불분명해지고 예기치 않은 렌더링 동작을 유발함.

### 3.3. 결과 계산 예외 처리 부재
*   `calculateResult` 서버 액션 호출 중 네트워크 지연이나 DB 연결 이슈로 에러가 발생할 경우, 클라이언트 상태가 `analyzing` 단계에 고착되어 사용자에게 아무런 피드백을 주지 못함.

---

## 4. 해결 방법 (Resolution)

### 4.1. Ref 기반의 정교한 파라미터 추적
*   `processedCharParamRef`를 도입하여 단순한 Boolean 플래그가 아닌, **현재 처리 완료된 구체적인 파라미터 값**을 기억하도록 수정.
*   '다시 하기' 클릭 시 현재 파라미터를 '처리 완료' 상태로 즉시 잠그고, URL 변경 후 충분한 시간이 지난 뒤에만 초기화하도록 로직 강화.

### 4.2. Suspense 적용 및 초기 상태 최적화
*   `ShingekiTestPage`를 `ShingekiTestContent`로 분리하고, 전체를 `Suspense`로 래핑하여 Next.js의 표준적인 쿼리 파라미터 처리 방식을 준수함.
*   컴포넌트 초기화 단계에서 `useSearchParams`를 통해 공유 파라미터를 즉시 확인하고 초기 상태(`step`, `result`)를 설정함으로써, 공유 URL 진입 시 홈 화면이 잠깐 나타나는 현상(Flash of Home Screen)을 근본적으로 제거함.

### 4.3. 상태 전이 및 예외 처리 보강
*   `calculateResult` 호출에 `try-catch-finally` 블록을 적용하여 에러 발생 시 홈 화면으로 안전하게 복구(Fallback)되도록 수정.
*   `handleRetry` 시 상태 초기화 순서를 엄격히 조정하여 UI 깜빡임 최소화.
*   `handleStart`를 통해 테스트 시작 시, 브라우저 URL에 파라미터가 남아있다면 명시적으로 삭제(`router.replace`)하여 테스트 진행 중의 상태 안정성을 강화함.

---

## 5. 향후 예방 조치 (Prevention)

*   **쿼리 파라미터 동기화**: URL 상태와 리액트 상태가 충돌하지 않도록 `router.replace` 완료 후 상태를 변경하는 패턴 지향.
*   **로딩 및 에러 상태 강화**: 서버 액션 호출 시 타임아웃 처리를 추가하여 무한 로딩 방지.
*   **테스트 케이스 추가**: 공유 URL 진입 시나리오에 대한 리그레션 테스트 자동화 검토.
