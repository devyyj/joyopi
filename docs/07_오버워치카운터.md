# 07. 오버워치 카운터 맵 (Overwatch Counter Map)

이 문서는 오버워치 영웅 간의 카운터(상성) 관계를 **관계 네트워크 그래프**로 시각화하는 **'오버워치 카운터 맵'** 페이지의 기능 정의서 및 개발 계획입니다.

---

## 1. 개요 및 목적
- **목적**: "이 영웅은 누구에게 강하고, 누구에게 약한가?"를 한눈에 파악할 수 있도록 영웅 간 카운터 관계를 그래프로 보여줍니다.
- **주요 가치**:
  - 전체 영웅의 상성 구조를 하나의 관계도로 조망할 수 있습니다.
  - 특정 영웅을 선택하면 그 영웅을 중심으로 **"내가 잡는 영웅" / "나를 잡는 영웅"** 관계만 강조되어 픽 판단에 바로 활용할 수 있습니다.
  - 필터 없이 모든 영웅을 한 화면에 보여주고, 상성은 항상 '유리' 이상인 관계만 표시해 핵심 상성에 집중합니다.

### 1.1. 결정 사항
| 항목 | 결정 | 비고 |
|---|---|---|
| 데이터 소스 | 정적 TS 데이터 파일 | `shingekiData.ts`와 같은 방식. DB·외부 API 의존 없음, 패치 시 파일 수정 |
| 시각화 | 관계 네트워크 그래프 | 영웅 = 노드, 카운터 = 방향 있는 화살표 |
| 영웅 이미지 | `public/images/overwatch/`에 초상화 저장 | 정적 에셋, `next/image` 사용 |
| 접근 권한 | 누구나 접근 | 네비게이션 메뉴에 공개 노출 |
| 라우트 | `/overwatch` | |

### 2.1. 상단 툴바
- **필터 없음 (2026-10-17 변경)**: 역할·상성 강도 필터를 제거했습니다. 모든 영웅을 항상 표시하고, '유리(2)' 이상 관계만 그립니다.
- **영웅 검색**: 이름(한글/영문) 입력 시 해당 노드를 선택하고 화면 중앙으로 이동합니다.
- **데이터 기준 표시**: 데이터가 어느 시즌/패치 기준인지 표기합니다 (`OVERWATCH_DATA_VERSION`).

### 2.2. 그래프 영역 (메인)
- **노드**: 원형으로 자른 영웅 초상화. 테두리 색상으로 역할 구분 (돌격: 파랑, 공격: 빨강, 지원: 초록).
- **간선**: `A ──▶ B` 는 "A가 B를 카운터한다"를 의미합니다. 상성 강도에 따라 선 두께/불투명도를 다르게 표시합니다.
- **기본 상태**: 모든 노드와 '유리' 이상 간선을 표시합니다.
- **노드 선택(클릭/탭)**:
  - 선택된 노드에서 나가는 간선(내가 잡는 영웅)은 초록 계열, 들어오는 간선(나를 잡는 영웅)은 빨강 계열로 강조합니다.
  - 연결되지 않은 노드와 간선은 흐리게(opacity 0.15) 처리합니다.
  - 빈 영역 클릭 시 선택을 해제합니다.
- **노드 호버(데스크톱)**: 영웅 이름 툴팁을 표시합니다.
- **좁은 화면**: 그래프 영역은 최소 폭 620px을 유지하며 가로 스크롤되고, 툴바의 영웅 선택 상자로 영웅을 고를 수 있습니다.

### 2.3. 상세 패널 (우측 / 모바일은 그래프 아래)
- 선택한 영웅의 초상화, 이름, 역할.
- **내가 잡는 영웅** / **나를 잡는 영웅** 목록을 강도 내림차순으로 정렬해 표시하고, 각 항목에 카운터 사유(예: "공중 유닛을 히트스캔으로 견제")를 함께 보여줍니다.
- 목록 항목 클릭 시 해당 영웅으로 선택이 이동합니다 (그래프 탐색).

### 2.4. 반응형
- **Desktop (lg 이상)**: 그래프 좌측 + 상세 패널 우측 고정.
- **Mobile**: 툴바·그래프·상세 패널이 세로로 쌓입니다. 그래프는 가로 스크롤, 영웅 선택은 선택 상자를 함께 제공합니다.

## 3. 데이터 설계 (정적 TS 파일)

`app/actions/overwatchData.ts`에 영웅 목록과 카운터 관계를 정의합니다. (기존 `shingekiData.ts`와 같은 위치·방식)

```typescript
export type HeroRole = 'tank' | 'damage' | 'support';

export interface Hero {
  id: string;          // 'genji' 처럼 영문 소문자 slug. 이미지 파일명과 일치
  name: string;        // '겐지'
  nameEn: string;      // 'Genji' (검색용)
  role: HeroRole;
  imageUrl: string;    // '/images/overwatch/genji.png'
}

export type CounterStrength = 1 | 2 | 3; // 1: 약간 유리, 2: 유리, 3: 매우 유리

export interface CounterRelation {
  counter: string;     // 카운터하는 영웅 id
  target: string;      // 카운터당하는 영웅 id
  strength: CounterStrength;
  reason: string;      // 카운터 사유 한 줄 설명
}

export const OVERWATCH_DATA_VERSION = '시즌 N (YYYY-MM)';
export const HEROES: Record<string, Hero> = { /* ... */ };
export const COUNTERS: CounterRelation[] = [ /* ... */ ];
```

### 3.1. 데이터 무결성 규칙 (테스트로 강제)
- `COUNTERS`의 `counter`, `target`은 모두 `HEROES`에 존재하는 id여야 합니다.
- 자기 자신을 카운터할 수 없습니다 (`counter !== target`).
- 같은 `(counter, target)` 쌍은 한 번만 정의합니다.
- 서로 모순되는 관계(A→B 와 B→A 가 동시에 존재)는 금지합니다. 상성이 대등하면 관계를 정의하지 않습니다.
- 모든 영웅의 `imageUrl` 파일이 `public/` 아래에 실제로 존재해야 합니다.
- `reason`은 빈 문자열일 수 없습니다.

### 3.2. 데이터 작성 방침
- 영웅 목록은 **구현 시점의 최신 로스터**를 공식 영웅 페이지 기준으로 확인하여 작성합니다.
- 카운터 관계는 세 출처를 합산해 정합니다 (2026-10-17 수집): counterwatch.gg 매치 통계(킬 교환·한타 결과 기반 카운터 점수), rankedboost.com 영웅별 카운터 평가·사유, games.gg 카운터 가이드(2026-03). 출처별 점수를 더해 '유리(2)' 이상만 남기고, 대상 영웅당 '나를 잡는 영웅'은 2~6명으로 둡니다. 서로를 카운터하는 관계는 점수가 높은 쪽만 남깁니다.
- 패치로 상성이 바뀌면 이 파일과 `OVERWATCH_DATA_VERSION`만 수정합니다.

### 3.3. 영웅 이미지
- `public/images/overwatch/{id}.png` 에 정사각형 초상화를 저장합니다.
- `scripts/download_overwatch_portraits.js` 가 OverFast API(`/heroes?locale=ko-kr`)의 영웅 목록과 초상화를 내려받아 `sharp`로 128×128 PNG로 축소해 저장합니다. 신규 영웅이 추가되면 이 스크립트를 다시 실행한 뒤 `overwatchData.ts`에 영웅과 관계를 추가합니다.
- 2026년 10월 기준 로스터는 54명(돌격 15 · 공격 23 · 지원 16)입니다.
- 초상화는 Blizzard 저작물이므로 비상업적 팬 페이지 용도로만 사용하고, 페이지 하단에 출처 및 저작권 고지를 표시합니다.
- 정적 로컬 파일이므로 `next.config.ts`의 `remotePatterns` 수정은 필요 없습니다.

## 4. 기술 설계

### 4.1. 그래프 렌더링 (디자인 초안 확정 후 변경)
- 외부 그래프 라이브러리 없이 **React로 직접 렌더링**합니다. 신규 패키지 없음.
  - 간선(곡선 + 화살촉)은 SVG `<path>`, 노드는 SVG 위에 % 좌표로 겹친 HTML `<button>` + `next/image` 초상화입니다.
  - 노드가 HTML 버튼이므로 키보드 접근·`aria-label`·이미지 최적화를 그대로 활용할 수 있습니다.
- 줌/팬은 제외하고, 좁은 화면에서는 그래프 영역을 가로 스크롤(최소 폭 620px)하고 **영웅 목록 선택 상자**로 보완합니다.

### 4.2. 레이아웃 전략: 역할별 원형 배치
- 영웅을 역할 순서(돌격 → 공격 → 지원)로 원 위에 배치하고, 역할 사이에 빈 칸을 하나씩 둡니다. 돌격 묶음은 원의 위쪽 중앙에 옵니다.
- 간선은 두 노드의 중점에서 원 중심 쪽으로 당긴 제어점을 쓰는 2차 베지어 곡선이라 선이 원 안쪽으로 모입니다.
- 위치가 항상 같아(결정적) 사용자가 영웅 위치를 기억하기 쉽고, force 배치보다 선 엉킴이 적습니다.
- 계산은 순수 함수(`computeRingLayout`, `computeSectorLabels`, `edgeGeometry`)로 분리해 테스트합니다.
- 노드 이름은 선택한 영웅과 연결된 영웅에만 표시하고, 나머지는 툴팁(`title`)으로 제공합니다.

### 4.3. 렌더링 및 하이드레이션 안전성
- `page.tsx`는 Server Component로 두고 메타데이터만 정의합니다.
- 그래프는 `'use client'` 컴포넌트에서 렌더링합니다. 좌표 계산이 결정적이므로 SSR 결과와 일치하지만, 만약 `next/dynamic`의 `ssr: false`가 필요하면 **반드시 Client Component 안에서만** 사용합니다 (지침 5.4, 6.7).
- 브라우저 전용 API(예: `matchMedia`로 모바일 판별)는 `useEffect` 안에서만 검사합니다 (지침 6.6).
- SVG 안의 초상화는 `<image>` 대신 `<clipPath>` + `<image href>` 를 사용합니다. 상세 패널의 초상화는 `next/image`에 `sizes`를 지정합니다 (지침 5.1).

### 4.4. 파일 구조
```
app/
├── actions/
│   ├── overwatchData.ts              # 영웅·카운터 정적 데이터
│   └── overwatchData.test.ts         # 데이터 무결성 테스트
└── overwatch/
    ├── page.tsx                      # Server Component, 메타데이터
    ├── fonts.ts                      # 제목용 Black Han Sans (next/font)
    ├── lib/
    │   ├── counter-graph.ts          # 순수 함수: 조회·강도 거르기·강조 상태·검색·원형 배치·곡선 계산
    │   └── counter-graph.test.ts
    └── components/
        ├── counter-map-client.tsx    # 상태(선택·검색) 관리 최상위 클라이언트 컴포넌트
        ├── counter-map-client.test.tsx
        ├── counter-graph.tsx         # 원형 관계도 (SVG 간선 + HTML 노드)
        ├── graph-toolbar.tsx         # 검색, 영웅 선택 상자
        ├── hero-detail-panel.tsx     # 선택 영웅 상세 패널
        └── theme.ts                  # 색상 토큰
public/images/overwatch/*.png         # 영웅 초상화
scripts/download_overwatch_portraits.js
```

### 4.5. 순수 함수 (`counter-graph.ts`)
| 함수 | 설명 |
|---|---|
| `getCountersOf(heroId)` | 이 영웅이 카운터하는 관계 목록 (강도 내림차순) |
| `getCounteredBy(heroId)` | 이 영웅을 카운터하는 관계 목록 (강도 내림차순) |
| `filterEdges(counters, heroes, { role, minStrength })` | 최소 강도(화면에서는 항상 2) 미만 관계를 제외 |
| `getEdgeKind(edge, selectedId)` / `getNodeState(heroId, selectedId, edges)` | 간선 `out / in / dim / base`, 노드 `selected / out / in / dim / normal` 상태 계산 |
| `searchHero(query)` | 한글·영문 이름 부분 일치 검색 (대소문자·공백 무시) |
| `computeRingLayout(heroes, ring)` / `computeSectorLabels` | 역할별 원형 배치 좌표와 역할 라벨 위치 (결정적) |
| `edgeGeometry(from, to, center, opts)` | 원 중심 쪽으로 휘는 곡선 경로와 화살촉 경로 |

1. 선택/해제 시 framer-motion 또는 CSS transition으로 부드러운 강조 전환.
2. Playwright(헤드리스)로 데스크톱·모바일 뷰포트 스크린샷 확인 — 그래프 가독성, 좁은 화면 레이아웃.
3. `npm run verify` (lint → test → git 추적 → 프로덕션 빌드) 통과 확인 후 보고. 커밋/머지는 사용자 승인 후 진행.
